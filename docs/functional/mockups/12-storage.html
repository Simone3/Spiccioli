New file… asks where to put it and writes it there and then, seeded with the 27 categories and nothing else. There is never an unsaved ledger: the open file is a file on disk from its first second (§12.1).

This file must be upgraded
finances-2016.spiccioli
Written by schema3
This version reads5

Opening it will convert it to schema 5. A copy of the file as it stands is written to the backup folder first, as finances-2016-2026-08-08-1432-pre-upgrade and as one of the ten kept there — it will be rotated out in time, so move it elsewhere if you want to keep it. If that copy cannot be written the upgrade does not run, and this dialog says why. The categorisation rules will be re-applied to every automatically categorised transaction as part of the upgrade; rows you categorised by hand are left alone. After the upgrade, Spiccioli 1.2 and earlier will no longer be able to open it.

§12.2

The File menu · switching files

File
the whole menu
New…a fresh file, categories seeded
Open…browse for one
Open Recent ▸the same list the launch screen offers
Quitends the session

All four close the open file, and every one of them takes its closing backup — as does closing the window without quitting. However the file stops being the open file, that is a close (§12). Everything else the application does, it does on a screen. There is no Edit menu because there is no undo (§12), and no View menu because there is nothing to configure about the view.

Switching files
Open… or Open Recent, mid-session
1 · the open fileautosaved, backed up, closed
2 · the new fileopened, nothing written
3 · schemachecked as at launch
4 · the screenPortfolio, filters cleared

Leaving a file closes it, so it takes its closing backup exactly as quitting would — and only if the session changed something. The file being opened goes through exactly what a file opened from the launch screen goes through: the same upgrade prompt, the same refusal if it cannot be understood. If it is refused, the file you had stays open and the message says why; the launch screen is not brought back mid-session.

§12

When the file cannot be written

Retrying
attempt 2 of 5 · a line on whatever screen you are on

The file could not be written. Trying again — your work is here and nothing has been lost.

Sidebar save stateNot saved — retrying
The sessioncarries on, fully editable

Five attempts in all, spaced a few seconds apart rather than fired back to back: a sync client holding the file, a volume away for a moment and an antivirus pass all clear on their own, given the moment. A retry that succeeds clears the line and puts Saved 14:32 back with no further ceremony.

The file cannot be written
finances.spiccioli · after 5 attempts
Location~/Documents
The system saidNo space left on device
Your workstill in memory, unwritten

One of the two errors in the application that block a screen — the other is a file that cannot be read (§14). Retry runs the same write: succeeding puts the session back exactly where it was, failing shows this again with whatever the system said this time. There is no Continue anyway and no Save As… — one file is the model, and typing on over a file that cannot keep it is the one thing worse than stopping.
